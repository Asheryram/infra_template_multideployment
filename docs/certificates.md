# Certificates

Traefik serves one **wildcard certificate** for `*.DOMAIN` (console, auth, hooks, every app and preview). How it is obtained depends on `TLS_MODE`:

| `TLS_MODE` | Certificate | You do |
|---|---|---|
| `letsencrypt` | issued and **renewed automatically** by Traefik (DNS-01, needs `DNS_PROVIDER` + token) | nothing |
| `selfsigned` | generated by the platform (browsers warn once **per hostname**), or one you import | `infra platform cert import` for a trusted one |
| `external` | held by the proxy that already owns 80/443 | renew it there |

## See what is being served

```bash
sudo -u deploy infra platform cert status
```

Shows the names, issuer, expiry (days left) and whether it is self-signed or imported. `infra platform up` also **warns** when the certificate expires within 30 days.

## Replace the self-signed certificate (selfsigned mode)

```bash
sudo -u deploy infra platform cert import /path/to/wildcard.crt /path/to/wildcard.key
sudo -u deploy infra platform up        # re-renders the TLS config so Traefik reloads it
```

The command refuses the import unless the file is a PEM certificate (a full chain is fine), the key is an unencrypted PEM key that **belongs to the certificate**, the certificate covers `*.DOMAIN`, and it is not expired. Nothing is touched when a check fails. The previous certificate is kept as `wildcard.crt.bak`. An imported certificate is **never replaced automatically**: when it nears expiry you get a warning, and you import the renewed one.

### Local testing without browser warnings (mkcert)

A browser calls an app's API on a *different hostname* than the page (the shop frontend does), so with a self-signed certificate each host needs its own exception — or the page shows "Failed to fetch". A locally trusted certificate removes that for good.

1. On Windows: install [mkcert](https://github.com/FiloSottile/mkcert) (`choco install mkcert` or `scoop install mkcert`), then once: `mkcert -install` (adds its CA to the Windows and browser trust stores).
2. Create the certificate for your domain: `mkcert -cert-file wildcard.crt -key-file wildcard.key "*.127-0-0-1.sslip.io" 127-0-0-1.sslip.io`
3. Copy both files into WSL (for example `\wsl$\Ubuntu\tmp\`) and run the two commands above.

Only machines where `mkcert -install` was run trust it — for teammates use a real certificate.

### Production with a self-signed or internal-CA certificate

Same command. If your own CA signed it, install the CA on every device that must trust it. Note that GitHub-hosted runners do **not** trust a self-signed or private-CA certificate, so signed deploy webhooks to `hooks.DOMAIN` fail; use `TLS_MODE=letsencrypt` (or a publicly trusted certificate) in production.
